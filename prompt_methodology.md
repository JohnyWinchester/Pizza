# Применение методики Chain-of-Thought (CoT)

## Выбранная сложная задача
**Задача:** Реализация полноценной корзины покупок с сохранением состояния в `localStorage` и реактивной синхронизацией UI.

## Почему применен CoT
Задача включает в себя управление состоянием, побочные эффекты (side effects) и работу с браузерным API. Попытка сгенерировать всё одним промптом часто приводит к галлюцинациям, пропущенным edge-case (например, очистка localStorage) или неоптимальной архитектуре. Разбиение на шаги гарантирует контроль над каждым аспектом.

---

## Шаг 1: Проектирование структуры данных и хука
**Логика шага:** Сначала нужно определить, как данные хранятся и мутируют, прежде чем рисовать UI.
**Промпт для AI:**
> "Спроектируй кастомный React-хук `useCart`. Он должен управлять массивом объектов `{id, name, price, quantity}`. Реализуй функции: `addItem`, `removeItem`, `updateQuantity`. Добавь `useEffect` для синхронизации состояния с `localStorage` при каждом изменении. Верни также вычисляемое свойство `totalPrice` через `useMemo`. Выдай только код хука на JS с JSDoc."
**Результат:** Чистый, изолированный хук, который можно протестировать отдельно от UI.

---

## Шаг 2: Реализация UI-компонента корзины
**Логика шага:** Теперь, когда логика готова, мы фокусируемся исключительно на отображении и пользовательском взаимодействии.
**Промпт для AI:**
> "Используя хук `useCart`, создай компонент `CartSidebar`. Он должен отображать список товаров (название, цена, количество, кнопки +/-), итоговую сумму и кнопку 'Оформить заказ'. Используй Tailwind CSS для стилизации. Обработай edge-case: если корзина пуста, покажи заглушку с иконкой и текстом 'Корзина пуста'. Выдай полный код компонента."
**Результат:** Готовый UI-компонент, который делегирует всю сложную логику хуку из Шага 1.

---

## Шаг 3: Написание тестов для проверки логики
**Логика шага:** Убедиться, что реализованная логика работает корректно, особенно сохранение в `localStorage` и расчет суммы.
**Промпт для AI:**
> "Напиши 3 модульных теста для хука `useCart` с использованием Vitest и `@testing-library/react`. 
> 1. Тест добавления нового товара.
> 2. Тест изменения количества существующего товара.
> 3. Тест проверки, что при инициализации хук читает данные из `localStorage` (используй моки для `window.localStorage`).
> Выдай код тестов."
**Результат:** Набор автотестов, подтверждающих надежность решения перед интеграцией в основной проект.

---

## Вывод по применению CoT
Разбиение задачи на 3 шага позволило:
1. Избежать перегруженного промпта, который AI мог бы частично "забыть".
2. Получить более качественный и специализированный код для каждого слоя (логика → UI → тесты).
3. Легко локализовать ошибку, если бы она возникла (мы бы точно знали, на каком шаге она появилась).
