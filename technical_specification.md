# Техническое задание (ТЗ) для AI-инженера

## 1. Функциональные требования

1. Система должна отображать сетку из минимум 6 карточек товаров (3 пиццы, 3 напитка) при загрузке главной страницы, чтобы пользователь мог сразу начать выбор.
2. Система должна фильтровать отображаемые карточки товаров по категориям ("Пицца", "Напитки") при клике на соответствующие табы в течение 100 мс, чтобы обеспечить мгновенный отклик интерфейса.
3. Система должна добавлять товар в глобальное состояние корзины при нажатии кнопки "В корзину" на карточке товара, чтобы сохранить выбор пользователя.
4. Система должна отображать боковую панель или модальное окно корзины при нажатии на иконку корзины в шапке, чтобы пользователь мог просмотреть свой выбор.
5. Система должна пересчитывать итоговую сумму заказа в реальном времени при каждом изменении количества товара (нажатие "+" или "-"), чтобы пользователь всегда видел актуальную цену.
6. Система должна автоматически удалять позицию из корзины, если пользователь уменьшает её количество до 0, чтобы избежать нулевых строк в чеке.
7. Система должна отображать встроенную Яндекс.Карту с центром в координатах 55.7887, 49.1221 (Казань) в блоке оформления заказа, чтобы визуализировать зону доставки.
8. Система должна блокировать кнопку "Оформить заказ", если поля "Имя" или "Телефон" не прошли валидацию (телефон: ровно 11 цифр), чтобы предотвратить отправку некорректных данных.
9. Система должна очищать состояние корзины и показывать экран успеха после успешной имитации отправки заказа, чтобы завершить пользовательский сценарий.

## 2. Нефункциональные требования

1. Время первой отрисовки контента (FCP) не должно превышать 1.5 секунды при имитации сети 4G, чтобы обеспечить быстрое впечатление от приложения.
2. Приложение должно корректно отображаться и быть полностью функциональным на экранах шириной от 320px (мобильные устройства) до 1920px (десктоп), чтобы охватить всю целевую аудиторию.
3. Все интерактивные элементы (кнопки, табы) должны иметь область нажатия не менее 44x44 пикселей, чтобы соответствовать стандартам мобильной доступности (a11y).
4. Код приложения должен быть написан с использованием функциональных компонентов React и хуков, без использования классовых компонентов, чтобы обеспечить единообразие кодовой базы.
5. Стилизация должна осуществляться исключительно через утилитарные классы Tailwind CSS, без создания отдельных файлов `.css` или `.scss`, чтобы упростить поддержку.

## 3. Оптимизация требований
**Проведенная оптимизация:** Требования 5 и 6 (пересчет суммы и удаление при 0) объединены в логическую группу "Управление состоянием корзины", так как они зависят от одного и того же хука `useCart`. Это устраняет дублирование логики при реализации и тестировании. Зависимости не нарушены: валидация (требование 8) логически зависит от наличия товаров (требование 3), что учтено в UX-решениях (блокировка кнопки при пустой корзине).
