### Краткое обоснование оценок

- **Bolt.new** — лидер по скорости прототипирования «с нуля», встроенный деплой и GitHub-интеграция из коробки. Слабее в глубокой кастомизации и работе с локальными файлами.
- **Replit Agent** — мощный облачный инструмент полного цикла, но бесплатный тариф ограничен, а экспорт кода требует лишних действий.
- **Cursor** — лучший баланс для работы с существующим кодом (глубокое понимание проекта через `@Codebase`), но требует установки и настройки.
- **GitHub Copilot** — отличная скорость автодополнения, но слабее в генерации целых проектов с нуля по сравнению с Cursor.

## 2. Отчёт

### 2.1. Описание задачи и требований

**Выбранная задача:** создание MVP веб-приложения для службы доставки пиццы и напитков в Казани.

**Ключевые требования:**

- **Технологический стек:** React + Vite + Tailwind CSS (ванильный JS рассматривался как альтернатива).
- **Сложность:** средняя — каталог с фильтрацией (пицца / напитки), корзина с динамическим подсчётом суммы, форма оформления заказа, интеграция Яндекс.Карты с центром на Казани (координаты 55.7887, 49.1221).
- **Необходимость доступа к локальным файлам:** высокая — агент должен уметь читать и редактировать HTML, CSS, JS, изображения, конфиги.
- **Требования к безопасности данных:** низкая/средняя — на этапе MVP нет реальных платёжных шлюзов, только сбор контактных данных.
- **Бюджет:** ограниченный (студенческий проект), приоритет — бесплатные или условно-бесплатные инструменты (Free Tier).

**Фиксация требований:** данный анализ использован как основа для сравнения Cloud- и IDE-агентов на следующем шаге.

### 2.2. Анализ инструментов

Сравнение проводилось по двум категориям:

**Cloud-агенты** (работают в браузере, код хранится в облаке провайдера):
- Bolt.new
- Replit Agent

**IDE-агенты** (работают локально, код остаётся на машине разработчика):
- Cursor
- GitHub Copilot

Ключевое различие для данного проекта: Cloud-агенты выигрывают в скорости старта «с нуля» и встроенном деплое, IDE-агенты — в глубине работы с кодом и безопасности данных.

### 2.3. Обоснование выбора

**Выбранный инструмент:** Bolt.new (Cloud-агент)

**Ключевые факторы, повлиявшие на решение:**

1. **Нулевой порог входа** — не требует установки, работает прямо в браузере. Для MVP это критично: первый рабочий прототип получен за 5 минут.
2. **Встроенный деплой** — после генерации код автоматически публикуется по ссылке, что удобно для демонстрации курсового проекта.
3. **Автоматическая интеграция с GitHub** — репозиторий создаётся сам, что соответствует требованиям сдачи ДЗ.
4. **Отличная работа с полным стеком** — Bolt.new сам создаёт структуру проекта, устанавливает зависимости и настраивает окружение.
5. **Бесплатный тариф** — 300K токенов в день достаточно для итеративной разработки студенческого проекта.

**Почему не подошли альтернативы:**

- **Cursor** — рассматривался как основной кандидат из-за глубокой работы с локальным кодом и максимальной оценки в таблице. Однако на этапе установки и первичной настройки возникли технические сложности, которые не удалось оперативно устранить в рамках дедлайна ДЗ1.
- **GitHub Copilot** — требует существующей кодовой базы и IDE, не генерирует проекты с нуля.
- **Replit Agent** — близкий конкурент Bolt.new, но бесплатный тариф более ограничен, а экспорт кода менее удобен.

### 2.4. Описание процесса настройки

Bolt.new не требует установки — настройка свелась к регистрации и авторизации:

1. Переход на [bolt.new](https://bolt.new)
2. Авторизация через GitHub-аккаунт (обязательно — для автоматического создания репозитория)
3. Нажатие «Start New Project»
4. Ввод стартового промпта с описанием задачи
5. Ожидание генерации → получение работающего сайта + ссылки на деплой + ссылки на GitHub-репозиторий

**Настройка MCP:** для Bolt.new не требуется — инструмент работает в собственном облачном окружении.

### 2.5. Примеры работы с инструментом

**Стартовый промпт:**
Создай MVP сайта службы доставки пиццы и напитков в Казани.
Технологии: React + Vite + Tailwind CSS.
Функционал:
Шапка с логотипом "Пицца Казань" и иконкой корзины
Фильтр меню по категориям: "Пицца" и "Напитки" (кнопки-табы)
Каталог из 6 товаров (3 пиццы + 3 напитка) с карточками:
изображение-заглушка, название, цена, кнопка "В корзину"
Корзина (модальное окно или боковая панель):
список добавленных товаров с количеством
кнопки + / - для изменения количества
автоматический подсчёт итоговой суммы
кнопка "Оформить заказ"
Форма оформления заказа: имя, телефон, адрес доставки
Встроенная Яндекс.Карта с центром на Казани (координаты: 55.7887, 49.1221)
Дизайн: современный, тёплые цвета (оранжевый/красный акцент), адаптивная вёрстка.
Используй mock-данные для товаров. Код должен быть чистым, компоненты — переиспользуемыми.


**Результат:**
- Количество итераций: 1 (промпт сработал с первого раза)
- Сложности: не возникли, Bolt.new корректно интерпретировал все требования
- Итог: работающий сайт с каталогом, фильтрацией, корзиной и картой

### 2.6. Выводы и рекомендации

**Выводы:**

1. Bolt.new — оптимальный выбор для быстрого старта MVP-проекта «с нуля», особенно в условиях ограниченного времени и бюджета.
2. Для проектов с уже существующей кодовой базой и высокими требованиями к безопасности данных предпочтительнее IDE-агенты (Cursor, GitHub Copilot).
3. Cloud-агенты экономят время на настройке окружения, но ограничивают контроль над инфраструктурой.

**Рекомендации:**

- Для ДЗ2–ДЗ6 рекомендуется комбинировать Bolt.new (для генерации кода) с текстовыми AI-ассистентами (для написания документации, промпт-шаблонов, ТЗ) — это экономит токены.
- При возможности — параллельно настроить Cursor как резервный инструмент для работы с локальным кодом на этапах ДЗ4–ДЗ5.
- Внимательно следить за daily limit токенов (300K/день) и распределять крупные задачи (ДЗ4, ДЗ5) на несколько дней.
